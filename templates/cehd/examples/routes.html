Setting up a new page consists of two steps:

  1. Defining a "route" and some related information
  2. Creating a template for the route

Defining routes

The routes for most pages are defined in app_routing/config/edpsych/routes.yml. (We'll cover the pages that aren't there later.)

A typical route looks like this:


/edpsych/examples/:
    publish: true
    template: edpsych/examples/index.html
    template_data:
        meta_description: "Short description goes here."
        section: "nav-section"

Let's take one line at a time.

The route


/edpsych/examples/:

This corresponds to what comes after www.cehd.umn.edu. So in this case we'll get: www.cehd.umn.edu/edpsych/examples/.

The publish setting

This will prevent new routes (and pages) from going live if set to false. These routes (and pages) will still be visible on Drydock. Once a page is ready, change false to true.


/edpsych/examples/:
    publish: true

The template

This is the path to the template file within the app_routing/templates directory.


/edpsych/examples/:
    publish: true
    template: edpsych/examples/index.html

Template data

This is some extra information the template can use. In this example, we're providing some context for how the navigation is rendered (section) and a short description that gets inserted in the head element of the page.


/edpsych/examples/:
    publish: true
    template: edpsych/examples/index.html
    template_data:
        meta_description: "Short description goes here."
        section: "nav-section"

Rules and guidelines for using YAML

The formatting of this (and all) yaml files is very important.

The information in this file is converted into data by the application. The structure of the data and it's relationships are defined by very specific indentation. In order to maintain consistent structure, please follow these rules and guidelines:

Rule: indent your additions exactly like the other information in the file

That means indent using spaces and using the same pattern you see here:


/edpsych/examples/: # no indentation

    # the next three lines should be indented 4 spaces
....publish: true
....template: edpsych/examples/index.html
....template_data:

.......# the next two lines should be indented 8 spaces
.......meta_description: "Short description goes here."
.......section: "nav-section"

This is by far the most important rule. Mixing indentation can have catastrophic consequences for other pages on the site.

Rule: routes are case-sensitive

If you define a route as /about/, linking to it like /About/ (capital-A) will not work. Even though it's not intuitive a and A are two distinct characters. Therefore, /about/ and /About/ are considered two distinct routes.

Rule: end routes with a "/"

This system is configured to redirect urls missing an ending slash (/) to a route that does. For example, If someone goes to www.cehd.umn.edu/edpsych (no / at the end), they will be redirected to www.cehd.umn.edu/edpsych/ (/ at the end).

Always define your routes with an ending slash like in the examples above.

Guideline: use lowercase routes with unabbreviated hyphenated words

Mixes of uppercase and lowercase letters in routes will work, but to avoid confusion and keep things consistent, please make your routes all lowercase. It's also a good idea to avoid abbreviated words.

Good

/edpsych/this/is/a/registration/page/
/edpsych/registration-page/

Not so good

/edpsych/reg-pg/

While the above abbreviation may make sense to you, it might not be obvious to others.

/edpsych/RegistrationPage/

As noted above, routes are case-sensitive. A PascalCase route like this might seem intuitive, but it will be hard to remember later if characters should he upper or lowercase. Try to stick with the guideline of lowercase routes.

Guideline: try to keep routes in alphabetical order

Keeping routes in alphabetical order will make it easier for others to find where routes are defined.

For example, /about/ and routes within that section should come before /current/.

Guideline: try to organize your templates in a way that matches the route

Also, templates for the main page of a section should be named index.html.


/edpsych/examples/:
    publish: true
    template: edpsych/examples/index.html
    template_data:
        meta_description: "Short description goes here."
        section: "nav-section"

In the above example, "examples" is a section, i.e., it has related pages within it. Therefore we name the main examples template index.html.

Also, the template is in edpsych/examples/, making it easier to find because it's similar to the route.
