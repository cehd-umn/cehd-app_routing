Using Macros

Our templating system (Twig) has some nice features to help with repetitive tasks on pages.

Twig macros can help alleviate the pain of repetitive code across pages and prevent errors by keeping things consistent.

Google analytics click tracking

The macro for tracking click events will make it easier to consistently track events—including links to other sites.

Step one: include the macro

You have to include the macro to be able to use it. Macros are organized in app_routing/templates/macros

Make sure you put it at the top, preferably just after the "extends" declaration at the top:

{%- verbatim -%}
{% extends "edpsych/layout/section.html" %}
{%- import "macros/ga-tracking.html" as analytics -%}{# <-- the GA tracking macro #}{% endverbatim %}

Step Two: Use the macro

In the past we've included code like this for click tracking:

<a href="/link" onclick="ga('send', 'event', 'how to apply', 'click', 'csppmain');">Link</a>

That's a bad practice for two reasons:

  1. It violates separation of concerns by mixing JavaScript in with the HTML
  2. It will never be executed on a page that leaves the website

This site has JavaScript included in it on every page that is set up to work with the code that the GA tracking macro inserts.

Using the macro follows a very similar pattern, but looks like this instead: 

{%- verbatim -%}<a href="/link/" {{ analytics.add_tracking("send", "event", "how to apply", "click", "csppmain") }}>link</a>{% endverbatim %}

The events macro

Step one: include the loader macro

We're using a fancy animated loader for feeds. Using the loader macro ensures you'll get all the right markup and styles to create it without copying and pasting a bunch of divs.

Note: We use this same loader for all COPE tools including the people, research, events and info sessions.

This code should go near the top of the page before the main_content block.

{% verbatim %}
{%- import "macros/loader.html" as loader -%}{% endverbatim %}

Step two: Place the loader on the page where your feed will go

{% verbatim %}
<article class="third">
{{ loader.loader(
    "Alumni in the news",
    "h3",
    "alumni-news-container"
    ) }}{% endverbatim %}
</article>

The loader macro will render HTML like this:


<h3>Alumni in the news</h3>
<div id="alumni-news-container">
    <div class="loader small">
        <div class="loader-figure small"></div>
        <p class="loader-label">Loading&hellip;</p>
    </div>
</div>

And it looks like this:

{{ loader.loader( "Alumni in the news", "h3", "alumni-news-container" ) }}

You might have noticed that the content and markup in the rendered HTML matches the parameters we passed into the macro.

We passed in "Alumni in the news" and you can see that gets inserted into the heading.

You may also have noticed that the second parameter we passed in is "h3" and our heading is an h3.

Finally, we passed in "alumni-news-container" and that's what the id is for our alumni news container. (That'll be important later on, because we're going to tell the newsfeed macro to put the rendered newsfeed there.)

The loader macro has a few more parameters. Below is a list of parameters and their default values:

{{ table.start_table("Loader macro parameters") }} {{ table.heading_row( ["Order", "Parameter", "Description", "Default"]) }} {{ table.row( ["first", "Heading text", "What you want the heading to say", "Latest news"]) }} {{ table.row( ["second", "Heading tag", "Which heading tag to use", "h3"]) }} {{ table.row( ["third", "Container id", "Which heading tag to use", "news-container"]) }} {{ table.row( ["fourth", "Heading classes", "Any classes you want to add to the heading; i.e., margin-top-1", "None (no classes will be added)"]) }} {{ table.row( ["fifth", "Additional loader classes", "Any classes you want to add to the loader element", "small"]) }} {{ table.row( ["sixth", "Loader text", "Text to display while the feed is loading", "Loading…"]) }} {{ table.row( ["seventh", "Additional container classes", "Any additional classes you wish to add to the container for the feed content", "None (no classes will be added)"]) }} {{ table.row( ["eighth", "Use a heading", "Insert a heading before the container for the feed content", "true"]) }} {{ table.end_table() }}

Parameters must be passed in order. If you wish to override just some of the defaults, you can pass in null for the others like so:


{% verbatim %}
{# This example will only override the default for the third parameter #}
{{ loader.loader(
    null,
    null,
    "alumni-news-container",
    ) }}
{% endverbatim %}

Step three: include the eventsfeed macro

{% verbatim %}
{%- import "macros/events-feed.html" as eventsfeed -%}{% endverbatim %}

Step four: Call the macro inside a bottom_js block

{% verbatim %}
{% block bottom_js %}{{ parent() }}
    {# The call to parent() above is *very* important #}
    {{ events.events_feed_js(355) }}
{% endblock %}{% endverbatim %}

What we're doing here is inserting some JavaScript into the bottom_js block that will pull in an events feed and render it for us.

The call to parent() is critical. That makes sure we get all the JavaScript from the parent template. Since this macro (and many others) rely on JQuery, for example, we need to make sure we have all the JavaScript dependencies for it to work.

Okay, but the code sample above is a little cryptic. What's going on there?

Like the loader macro above, the events_feed_js macro takes several parameters. Often you'll only need one like the example above.

The events calendar "Link Pro" sets up query parameters to pull in different feeds. For example, an XML feed will look something like this: http://apps.cehd.umn.edu/events/Admin/XMLFeed.aspx?&r=1&q=6&t=355

t=355 above is the id for the tag we want to use. In many cases you won't need any more information than that. Thus, the tag id is the first parameter for pulling in events. So we call the macro like:
{% verbatim %}{{ events.events_feed_js(355) }}{% endverbatim %}.

News feed macro

The news feed macro is very similar to the events feed macro, except it takes different parameters.

Step one: import the macro

{% verbatim %}{% import "macros/news-feed.html" as newsfeed %}{% endverbatim %}

(See information about the loader above.)

Step two: Call the macro inside a bottom_js block

{% verbatim %}
    {% block bottom_js %}{{ parent() }}
        {{ newsfeed.news_feed_js("category/alumni-educational-psychology/feed/") }}
    {% endblock %}
    {% endverbatim %}

By default, news_feed_js renders the news stories in an element with an id of "news-container". The loader creates that by default.

Once you have the loader set up, you might only need to pass in the path to the feed on the news site as shown above. The macro defaults to using the news site for news feeds. The feed we're pulling in above is http://news.cehd.umn.edu/category/alumni-educational-psychology/feed/. The macro knows to use http://news.cehd.umn.edu/, so we just have to provide the rest of the information. Thus, we pass in category/alumni-educational-psychology/feed/.

To recap:

  1. Set up your loader.
  2. Call the news_feed_js macro and pass in the path to the feed.

Info session macro

If you've skipped to this part, make sure you understand how the loader works. The patterns there apply here as well.

By now hopefully you've read about how the other macros that load feeds work. If so, this should seem very familiar. If you've skipped ahead, start with the loader instructions and work your way back to here.

Import the macro


                {% verbatim %}
{% import "macros/info-sessions-feed.html" as info_session %}
                {% endverbatim %}

Call the macro inside a bottom_js block


                {% verbatim %}
{% block bottom_js %}{{ parent() }}
    {# The call to parent() above is *very* important #}
    {{ info_session.info_sessions_feed_js("McNair") }}
{% endblock %}
                {% endverbatim %}

The parameter we passed in above is the value for the code query parameter in the feed. I.e., https://apps.cehd.umn.edu/students/infosession/admin/RSSFeed.aspx?code=McNair
